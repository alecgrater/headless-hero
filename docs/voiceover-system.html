1. The Recording Tool

The voiceover recording tool is a full-page three-panel interface accessed from the timeline view. It provides a teleprompter-guided recording experience with multi-take management.

Three-Panel Layout

Panel Component Purpose
Left: Scene Navigator SceneNavigator.tsx Lists all narrated scenes. Shows recording status (mic icon: green = recorded, gray = pending). Filterable: All / Unrecorded / Flagged.
Center: Teleprompter TeleprompterPanel.tsx Displays narration text with animated timing needle. Shows scene image as video preview. Live audio level meter during recording.
Right: Take Panel TakePanel.tsx Manages multiple takes per scene. Play/select/delete takes. Import external audio files. Trim end point adjustment.

Recording Modes

  • Single — Records one scene at a time. Stops when you stop.
  • Continuous — After recording a scene, auto-advances to the next unrecorded scene.
  • Free — Records without scene constraints.
  • Rehearse — Plays back the teleprompter animation without capturing audio. Useful for practice runs.

Recording Flow

1. User selects microphone from device dropdown 2. User presses Space to begin 3. 3-2-1 countdown → needle glides from left edge toward first word 4. MediaRecorder starts → WebM/Opus encoding at 100ms chunk intervals 5. Teleprompter needle animates through words based on word_timestamps 6. User presses Space to stop 7. Blob uploaded via POST /api/recording/upload-take 8. Stored as data/projects/{script_id}/recording/takes/{scene_id}_take{N}.webm

Teleprompter Needle

The needle is a small purple arrow that indicates current reading position. Its position is computed by:

  1. Looking up which word should be active at the current elapsedMs
  2. Calculating the progress within that word: (elapsed - startMs) / (endMs - startMs)
  3. Interpolating the x-position between the current word's center and the next word's center
  4. If words span multiple visual lines, the needle follows the text flow
Word Highlighting

During recording, words change color to indicate state: white + scaled up = currently being spoken, gray = already spoken, slightly lighter = about to be spoken (500ms lookahead), dark + blurred = far ahead.

Technical Details

  • Audio capture: Web Audio API (MediaRecorder with audio/webm;codecs=opus)
  • Audio level: Real-time FFT analysis via AnalyserNode, updated every animation frame (~16ms)
  • Level meter: Normalized 0-1 from frequency bin average (appears in both toolbar and video preview area)
  • Device enumeration: navigator.mediaDevices.enumerateDevices(), with live monitoring stream on selected device
  • Session persistence: session.json stores selected takes, flagged scenes, trim points per scene
  • Timing offset: User-adjustable -500ms to +500ms slider to compensate for latency between reading and speaking

2. Word Timing: AI Voiceover (ElevenLabs)

AI Path Character-level alignment from ElevenLabs API

How It Works

  1. We call ElevenLabs' /v1/text-to-speech/{voice_id}/with-timestamps endpoint
  2. ElevenLabs returns base64-encoded MP3 audio plus an alignment object containing:
    • characters[] — every character in the input text
    • character_start_times_seconds[] — start time for each character
    • character_end_times_seconds[] — end time for each character
  3. We reconstruct word-level timestamps from character-level data via _reconstruct_words():
    • Groups non-whitespace characters between spaces
    • Word start = first character's start_time
    • Word end = last character's end_time
    • Converts seconds to milliseconds
  4. Duration is derived from the last word's end_ms (most accurate source)

Output Format

[
  { "word": "The",      "start_ms": 0,    "end_ms": 180  },
  { "word": "ancient",  "start_ms": 200,  "end_ms": 520  },
  { "word": "library",  "start_ms": 540,  "end_ms": 890  },
  ...
]

Accuracy

ElevenLabs alignment is highly accurate because the timestamps come directly from the synthesis model — they represent exactly when the model generated each phoneme. No post-hoc alignment needed.

Source: backend/integrations/elevenlabs_client.py — _reconstruct_words()

3. Word Timing: Real Voiceover (Whisper)

Real Path Post-hoc alignment via faster-whisper STT

How It Works

  1. During export, each selected take is converted from WebM to MP3 via FFmpeg with audio processing filters:
    • highpass=f=80 — removes low-frequency rumble
    • afftdn=nf=-20:tn=1 — FFT-based noise reduction
    • acompressor=threshold=-20dB:ratio=3:attack=5:release=150 — dynamic range compression
  2. The processed MP3 is fed to faster-whisper (OpenAI Whisper, C++ port) with:
    • Model: small (good accuracy/speed tradeoff for single-user desktop)
    • Device: CPU, compute type: int8 (no GPU required)
    • word_timestamps=True for word-level output
    • initial_prompt=narration_text — biases transcription toward the expected text
  3. Whisper returns segments with word-level timestamps (start/end in seconds)
  4. We convert to the same {word, start_ms, end_ms} format as ElevenLabs

Fallback: Even Distribution

If Whisper fails or returns no word timestamps:

  1. Get total audio duration via ffprobe
  2. If ffprobe fails, estimate at ~140 WPM (430ms per word)
  3. Distribute words evenly: each word gets duration_ms / word_count milliseconds
Accuracy Difference

Whisper alignment is less precise than ElevenLabs because it's doing speech recognition + alignment as a post-processing step on natural speech (variable pacing, breathing, pauses). ElevenLabs knows exactly when it synthesized each sound. Expect Whisper to be accurate to within ~50-100ms per word, whereas ElevenLabs is precise to ~10-20ms.

The initial_prompt Trick

By passing the narration text as initial_prompt, we bias Whisper to expect those specific words. This dramatically improves alignment accuracy for our use case because we know exactly what was supposed to be said — we just need to know when each word was spoken.

Source: backend/pipeline/audio_alignment.py

4. End-to-End Data Flow

Phrase Timestamps (Computed from Word Timestamps)

Both AI and real voiceover paths produce word_timestamps. These are then grouped into phrase_timestamps using an adaptive gap-based algorithm:

Algorithm: compute_phrase_timestamps()

  1. Calculate inter-word gaps: next_word.start_ms - current_word.end_ms
  2. Find the median gap across all word boundaries
  3. Set threshold: max(200ms, min(800ms, median_gap × 3))
  4. Walk through words — start a new phrase whenever a gap exceeds the threshold
  5. Output: list of {start_ms, end_ms} for each phrase

This produces natural phrase groupings that adapt to speech cadence. Fast speakers get shorter gaps (lower threshold), deliberate speakers get longer gaps.

5. Downstream Consumers

Everything downstream of the voiceover is format-agnostic — it doesn't know or care whether the audio came from ElevenLabs or a real recording. It just reads word_timestamps and phrase_timestamps.

Consumer Uses What It Does
SubtitleOverlay (Remotion) word_timestamps Groups words into display phrases (max 8 words, splits at punctuation/300ms pauses). Shows active phrase at bottom with word-level highlighting.
EliOverlay (Remotion) phrase_timestamps Drives mouth openness (0→1 continuous blend). Ramps open 40ms before phrase, stays open during, ramps closed 110ms after.
Zoom Punch FX word_timestamps Triggers zoom effect on a specific word. Looks up trigger_word in timestamps to find exact frame.
Scene Micro-Timeline word_timestamps Snaps image crossfade markers and FX triggers to word boundaries (100ms threshold).
Teleprompter (Recording) word_timestamps Guides recording needle position. Falls back to 140 WPM estimate if no timestamps exist yet.
Timeline Duration audio_duration_seconds Determines scene length in the global timeline. Audio duration is the source of truth for timing.

6. Considerations for Real Voiceover

Things That Work Differently With Real Voice

Timing Variability

AI voiceover has predictable, consistent pacing. Real voiceover has natural variation — pauses for emphasis, breathing gaps, speed changes, stumbles. This affects:

  • Subtitle display: Phrases may be shorter/longer than expected. The adaptive phrase grouping algorithm helps, but very long pauses (>800ms) might create awkward single-word phrases.
  • Eli mouth animation: More gaps between phrases = more mouth-closed time = more natural looking (actually a benefit).
  • Zoom punch timing: If you trigger on a word, natural delivery variance means the zoom might feel slightly different than with AI voice.

Audio Quality Concerns

  • Room noise: The FFmpeg filter chain (highpass + noise reduction + compression) helps, but can't fix a bad recording environment. AI voice has zero noise.
  • Plosives/sibilance: No de-essing or pop filter processing currently applied.
  • Volume consistency: The compressor helps, but across scenes recorded at different times, overall volume may vary.
  • WebM→MP3 quality: The recording is WebM/Opus → converted to MP3 192kbps. This is a lossy→lossy conversion. Not ideal for audiophiles but acceptable for YouTube.

Whisper Alignment Quality

  • initial_prompt helps a lot — but if the speaker deviates from the script (ad-libs, rephrases), Whisper may produce incorrect word boundaries
  • Mumbled or unclear words may get misaligned or dropped entirely
  • No validation against narration text — we don't currently verify that Whisper's transcription matches the expected script
  • Even distribution fallback is a rough approximation — if Whisper fails, subtitles will be noticeably off

Session Workflow Differences

  • Multiple takes: You'll likely need more takes than with AI (which is always perfect on the first try)
  • Flagging: Scenes you want to re-record later need the flag system
  • Duration variance: Each take of the same scene will be a different length. This changes the overall video duration every time you swap takes.
  • No word_timestamps for teleprompter guidance on first recording: If no AI voiceover was generated first, the teleprompter falls back to a ~140 WPM estimate for needle positioning

7. Things We May Be Forgetting

No Re-alignment After Take Swap

When you record multiple takes and select a different one, the word_timestamps in the scene only update on export. If you're previewing or checking timing in the timeline before exporting, you're still seeing timestamps from the previously exported take (or from AI generation). There's no on-the-fly alignment when selecting takes.

No Script Deviation Detection

If the speaker says something different from the narration text, we don't detect it. Whisper will transcribe what was said, but we don't compare it to what was expected. This could produce word_timestamps that don't match the displayed subtitles.

Retake Impact on Downstream State

When you re-export after re-recording, the new audio duration may differ. This invalidates:
- frame_timings set in the micro-timeline (image crossfade points become wrong)
- visual_in_seconds / visual_out_seconds if they exceed new duration
- Zoom punch trigger timing if it was manually fine-tuned
- Any rendered scene previews (now stale)

No Loudness Normalization Across Scenes

Each scene is processed independently. If you record Scene 3 in the morning and Scene 7 in the evening (different mic distance, room, energy level), they may have noticeably different loudness in the final video. There's no LUFS normalization pass.

Teleprompter Relies on Pre-existing Timestamps

The teleprompter needle needs word_timestamps to know where to point. For the very first recording of a scene (no AI voiceover generated first), it falls back to a flat 140 WPM estimate. This may not match natural speaking pace, making the needle feel "off" during recording.

No Monitoring / Playthrough

There's no audio monitoring (hearing yourself through headphones with processing applied in real-time). You only hear the raw mic. This means you can't judge the final processed sound until after export.

No Punch-In Recording

If you flub one sentence in a 30-second scene, you have to re-record the entire scene. There's no way to punch in at a specific word and only re-record a section.

8. Enhancement Ideas

Visual Rhythm + Tone Indicators

The big opportunity: make the teleprompter not just show what to say, but how to say it. Derive visual cues from the writing structure to promote controlled, rhythmic delivery.

Breath Markers

Detect natural breath points from punctuation and phrase boundaries. Show subtle indicators (a small pause icon or a vertical line) in the teleprompter at commas, periods, and long dashes. Different sizes for different pause lengths:

  • Comma / conjunction: thin line (beat pause, ~200ms)
  • Period / semicolon: medium line (breath pause, ~400ms)
  • Paragraph / section break: thick line (full breath, ~800ms)

This prevents rushing through text and promotes the deliberate pacing that sounds professional.

Emphasis Indicators

Highlight words/phrases that should be emphasized based on writing structure:

  • Key terms (proper nouns, technical terms) — subtle underline or bold
  • Contrast words ("but", "however", "instead") — indicate a tonal shift
  • List items — numbered indicators to maintain consistent rhythm across items
  • Question marks — rising intonation indicator (upward arrow?)

Could be AI-generated: pass the narration to Claude with a prompt asking which words carry emphasis.

Pace Guide / WPM Target

Show a real-time WPM counter during recording, with a target range indicator (e.g., green zone = 130-160 WPM). This helps maintain consistent pacing across scenes and recording sessions.

  • Calculate rolling 5-second WPM from word_timestamps (after recording) or from elapsed time (during)
  • Color-coded: too fast = amber, too slow = blue, target = green
  • Optional: subtle audio click track at desired pace (like a metronome but gentler)

Sentence-Level Intonation Curves

Display a subtle curve above each sentence indicating the expected pitch contour:

  • Statements: slight downward slope at end
  • Questions: upward curve at end
  • Lists: rising on items, falling on final item
  • Dramatic reveal: dip then rise ("What they found... was extraordinary")

This could be derived from punctuation + sentence structure analysis, or AI-annotated.

Energy/Intensity Zones

Color-code sections of the script based on intended energy level:

  • Calm/informational (blue) — steady, measured delivery
  • Building (amber) — increasing energy, slightly faster
  • Peak/impactful (red/purple) — maximum emphasis and presence
  • Cool-down (green) — winding back to conversational

Annotated either manually in the script editor or auto-generated based on content analysis.

Post-Recording Rhythm Visualization

After recording, show a waveform-style view of the take with:

  • Word boundaries overlaid on the waveform
  • Gaps between words visualized (too long? too short?)
  • Comparison between actual timing and ideal timing (if AI voiceover exists as reference)
  • Highlight sections where pace deviated significantly from average

This helps identify which parts of a take need re-recording without listening to the whole thing.

Waveform Preview in Take Panel

Show a mini waveform for each take in the take panel. Click anywhere on it to seek. Visually compare takes by shape to quickly identify the best one without playing them all.

AI Reference Playback

If AI voiceover was generated first, offer a "listen to reference" button that plays the AI version as a delivery guide. The speaker can hear the target pacing and emphasis before recording their own take.

Automatic Punch-In

Allow re-recording a portion of a scene:

  1. Mark a word range in the teleprompter as the "punch zone"
  2. Playback existing audio up to the punch-in point
  3. Auto-start recording at the punch point
  4. Auto-stop after the punch-out point
  5. Splice the new audio segment into the existing take

Requires FFmpeg splice + re-alignment of the combined audio.

Loudness Normalization

Add a LUFS normalization pass during export that ensures all scenes hit the same perceived loudness (e.g., -16 LUFS for YouTube). This is a single FFmpeg loudnorm filter addition but needs a two-pass approach for accuracy.

Script Deviation Warning

After alignment, compare Whisper's transcription to the expected narration. Flag scenes where the speaker deviated significantly (different words, skipped sentences, ad-libs). Show a diff-like view so the speaker can decide if the deviation is acceptable or needs a retake.

De-essing + Pop Filter (Digital)

Add optional FFmpeg filters for sibilance reduction and plosive removal. This makes real voiceover sound more polished without requiring physical pop filters:

-af "deesser=i=0.4:m=0.5,highpass=f=80"

Implementation Priority Recommendation

Priority Enhancement Rationale
HIGH Breath markers + Emphasis indicators Directly improves delivery quality with minimal implementation effort (text analysis only)
HIGH Live WPM pace guide Simple elapsed/word-count math, huge impact on consistency
