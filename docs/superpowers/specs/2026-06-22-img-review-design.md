# Img Review Design

## Goal

Add a project-level Img Review tab for correcting generated render-source images before rerendering and exporting a project. The first target is fixing generated image text artifacts, such as malformed calendar labels in "Your Life At Every Level Of Working At Burger King", but the workflow must work for any project.

## Scope

Img Review covers project render-source images only:

- Scene `image_url` assets, including title-card scene images.
- Scene `frame_urls` assets used by multi-frame and continuous scenes.
- Scene `visual_layers[].image_url` assets used by layered visual modes such as popup sequences, comparison boards, blink, and stat cards.

It intentionally does not include long-form thumbnails or short-form thumbnails in this version.

## User Experience

The Timeline project view gains a new top-level tab named `Img Review`, placed with the existing Segments, Visual Modes, Blink Review, Timeline, Thumbnails, and SEO tabs.

The tab shows a left-side or top-side review list of all editable generated images with scene context, asset type, and reviewed status. Selecting an item opens an editor with an image canvas and a compact tool bar.

The editor provides Preview-like basics:

- Eraser brush.
- Rectangle selection.
- Copy selection.
- Paste selection as a movable patch.
- Delete selection.
- Add text with color and size controls.
- Undo and redo for the current editing session.
- Save edited copy.
- Reset asset to original.

The UI is a dense production tool, not a landing page. It should use Tailwind utilities, dark neutral panels, icon buttons with tooltips where available, and restrained accent colors consistent with the timeline UI.

## Persistence Model

Edits are non-destructive.

Each editable asset has a stable asset id derived from its scene id and location:

- `scene:{scene_id}:image`
- `scene:{scene_id}:frame:{index}`
- `scene:{scene_id}:layer:{layer_id_or_index}`

The backend enumerates the current script JSON and returns an Img Review asset list. For each asset it includes:

- Asset id.
- Scene id.
- Segment index/name.
- Scene index.
- Asset kind.
- Current URL used by rendering.
- Original URL, from metadata when available or current URL when the asset has never been edited.
- Reviewed flag.
- Dimensions when readable.

Saving an edit writes a PNG under `data/projects/{script_id}/image_review/{safe_asset_id}/edit_{version}.png`, updates the matching script JSON field to point at `/static/projects/{script_id}/image_review/{safe_asset_id}/edit_{version}.png`, stores original/review metadata in `visual_source_metadata` or the visual layer metadata, and marks render inputs changed.

Reset restores the original URL into the matching script JSON field and preserves the edited files on disk for auditability. Existing exported videos remain unchanged until the user rerenders/reexports.

## Backend API

Add `backend/api/image_review.py` with:

- `GET /api/image-review/{script_id}`: list editable render-source assets.
- `POST /api/image-review/{script_id}/assets/{asset_id}/edit`: accept a base64 PNG data URL, save a new edited copy, update the target script JSON URL, mark render inputs changed, and return the refreshed asset plus script content.
- `POST /api/image-review/{script_id}/assets/{asset_id}/reset`: restore original URL and return refreshed asset plus script content.

The API validates that asset ids refer to assets inside the requested script. It only accepts PNG data URLs generated by the app. It never accepts arbitrary filesystem paths.

## Frontend Architecture

Add focused frontend files instead of expanding `TimelinePage.tsx` heavily:

- `frontend/src/types/imageReview.ts` for API response types.
- `frontend/src/components/timeline/image-review/imageReviewAssets.ts` for extracting labels and local editor helpers.
- `frontend/src/components/timeline/image-review/ImageReviewEditor.tsx` for the canvas editor.
- `frontend/src/components/timeline/image-review/ImageReviewTab.tsx` for loading, selection, save/reset actions, and review list layout.

`TimelinePage.tsx` only adds the tab key, imports the tab, and passes `scriptId`, current `ScriptContent`, and `state.setContent`.

## Rendering Impact

Because render-source URLs in script JSON are updated, Remotion automatically uses edited assets on the next render. The backend must call `mark_render_inputs_changed(script_id)` after save and reset so existing render cache entries are treated as stale.

## Testing

Backend tests cover:

- Asset enumeration for scene image, frame image, and visual layer image.
- Saving an edited PNG creates a non-destructive file, updates the correct script JSON field, records original/review metadata, and marks the asset reviewed.
- Reset restores the original URL.
- Invalid asset id and invalid data URL are rejected.

Frontend tests cover:

- Img Review tab lists render-source images and excludes thumbnails by construction.
- Editor can delete a selection and save the edited canvas through the API.
- Reset calls the reset API and applies returned script content.

Manual verification should include opening the app, visiting a project, selecting Img Review, editing one image, saving, checking the image URL updates in the UI, and rerendering/exporting after edits.

## Workflow Docs

Because this adds a new project-level review workflow before export, update in-app docs in the same change. The existing setup/authoring docs should mention Img Review as the place to correct generated scene images before render/export, and clarify that thumbnails are not included.
