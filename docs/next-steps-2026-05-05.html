What Changed: Two Big Feature Areas

VOICE Voiceover Enhancement Suite

A full recording system upgrade. This is on main (already merged).

  • Take alignment — POST /api/recording/align-take: realigns word timestamps to a newly recorded take using forced alignment. Instant teleprompter feedback shows where you drifted.
  • Script deviation detection — difflib-powered comparison between narration script and what was actually spoken. Shows colored inline diff + badge.
  • EBU R128 loudness normalization — Two-pass FFmpeg loudnorm targeting -16 LUFS. Frontend toggle per-export.
  • Breath markers — Punctuation-based pause indicators in teleprompter (commas = short, periods = long).
  • Real-time WPM counter — Color-coded zones during live recording (green/yellow/red).
  • Claude delivery annotations — Haiku marks emphasis words, energy zones, and question rises directly on the teleprompter.
  • AI reference playback — Play the ElevenLabs-generated TTS with a synchronized teleprompter needle so you can match cadence.
  • Adaptive teleprompter speed — Uses alignment data from previous takes to adjust scroll speed.
  • Mini waveform previews — wavesurfer.js per take in the take list.
  • De-essing + lowpass filters — Optional audio filters on export.
  • Rhythm analysis — Post-recording stats: WPM variance, gap distribution, pace curve.
  • Punch-in recording — Select a word range, re-record just that section, auto-spliced via FFmpeg.

VOICE Voiceover Quality Scoring

Also on main. Builds on the enhancement suite.

  • Per-take scoring — 5 dimensions (pacing, rhythm, accuracy, emphasis, engagement), scored 1-10 using algorithmic metrics + Claude Haiku qualitative assessment.
  • "Score All" button — Batch-scores every selected take in the session (background job with polling).
  • "Needs Work" filter — SceneNavigator sorts scenes by lowest score first, shows color-coded badges.
  • Recommendations — Low-scoring scenes get specific improvement text from Claude.

ELI Procedural Animation Rebuild

On eli_2 branch (not merged to main yet).

  • Old system removed — 150+ discrete pose images switched via AI-generated keyframe timelines. Looked choppy.
  • New system — Claude picks ONE pose per scene (via Haiku, very fast). Remotion applies procedural idle motion to that single PNG:
    • Breathing (~3.5s asymmetric dual-sine cycle)
    • Body sway (~7s, golden ratio to breathing)
    • Head micro-tilts (~5s, ease-into-holds)
    • Deterministic blinks (seeded schedule, 20% double-blink chance)
    • Lip sync (phrase_timestamps → open/closed mouth opacity blend)
    • Spring entrance + ease-out exit per scene
  • Character frame generation UI removed — No more Settings > Character page. The PNGs on disk are still used, just not generated/managed through the app anymore.
  • Determinism — All randomness seeded from hash(sceneId + frameId). Same input = same animation every render.

Testing Plan: Recommended Order

Start the app: npm run dev from the repo root. Backend on :8420, frontend on :5173.

  1. 1 Merge eli_2 to main
    Before testing anything, get on one branch.
    git checkout main && git merge eli_2
    This should merge cleanly since eli_2 only touches Eli files and main only touched voiceover/gameplay after it branched.
  2. 2 Sanity check: render a video with Eli
    Verifies the new procedural animation actually produces output.
    • Open an existing project that has voiceover already generated
    • Click "Add Eli" in the timeline (should be fast — Haiku picks 1 pose per scene)
    • Do a full render (Export panel > Render YouTube)
    • Watch the output — look for:
      • Breathing: subtle vertical scale oscillation
      • Sway: gentle lateral drift
      • Blinks: natural interval (3-6s), not robotic
      • Lip sync: mouth opens during speech, closes during silence
      • Entrance: springs in from below at scene start
      • Exit: slides down and fades at scene end
      • Corner changes between scenes
  3. 3 Record a voiceover with the new mic
    First real test of the recording suite with good hardware.
    • Open a project, go to Timeline > Record Voiceover (mic icon)
    • Verify the new mic shows up in the device dropdown
    • Record one scene. Check:
      • Breath markers visible in teleprompter (small dots at commas/periods)
      • Real-time WPM counter updates during recording
      • Take waveform appears in take list after recording
  4. 4 Test delivery annotations
    Claude Haiku annotates emphasis/energy.
    • In the recording page, look for a "Get Delivery Notes" or annotation button
    • Should mark emphasis words (bold/underline in teleprompter), energy zones (high/low), and question rises
    • Play the AI reference (ElevenLabs TTS) — check that the teleprompter needle follows along in sync
  5. 5 Test alignment + deviation
    Record a take where you deliberately change some words.
    • Record a take but swap a few words or skip a sentence
    • After recording, look for the deviation badge (should show % mismatch)
    • Click it to see the inline diff (your words vs. script)
    • Re-record and check that alignment data improves teleprompter speed on the next take
  6. 6 Test punch-in recording
    Re-record just a word range and verify the splice.
    • Select a word range in the waveform (should enter punch-in mode)
    • Record the replacement
    • Play back — verify the splice sounds natural (no click/pop at boundaries)
  7. 7 Test quality scoring
    Score your takes and verify recommendations are useful.
    • Record 3-4 scenes with varying quality (one careful, one rushed, one where you stumble)
    • Hit "Score All" in the top bar
    • Wait for scoring to complete (background job, should take 10-30s per scene)
    • Check score badges in the scene navigator — worst takes should show red/orange
    • Switch to "Needs Work" filter — lowest scores should sort to top
    • Check that recommendations make sense ("too fast", "missed emphasis on X", etc.)
  8. 8 Test loudness normalization
    Export with normalization ON and compare.
    • Export voiceover with loudness normalization toggle enabled
    • Compare volume levels across scenes — should be consistent at -16 LUFS
    • Listen for any artifacts from the loudnorm filter
  9. 9 Eli animation tuning
    If anything looks wrong in step 2, these are the knobs to turn.
    • File: remotion/src/effects/overlays/EliOverlay.tsx
    • Breathing amplitude: 0.004 primary, 0.0015 secondary (lines with breathScaleY)
    • Sway range: 3px lateral, 0.8° rotation
    • Tilt range: 1.5°
    • Blink interval: 3-6s (in generateBlinkSchedule)
    • Entrance spring: damping: 12, stiffness: 120
    • Overlay size: 280px (constant at top)
  10. 10 Full end-to-end
    Once individual pieces work, do a complete video.
    • Generate a script → images → record voiceover with new mic → score → fix low-scoring scenes → export with loudness normalization → add Eli → full render → watch

Known Issues / Things to Watch

Eli animation tuning: The sine frequencies and amplitudes in the Remotion component are starting values. Expect 2-3 visual iteration rounds after first watching a rendered video. The blink-as-squash technique may not read well at 280px overlay size — could need to increase scale or switch to a different blink approach.

eli_2 branch: Not merged to main yet. The Character section was removed from Settings — if you ever need to regenerate character frames in the future, you'd need to restore that or do it from the command line.
