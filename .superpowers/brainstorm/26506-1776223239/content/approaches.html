Proposed Approaches

Three ways to build the Eli vortex thumbnail + glass orb borders

A

Integrated into existing compositing pipeline (Recommended)

Keep everything in title_card_composer.py. During title card generation:

  1. Generate all segment circle images normally (existing flow)
  2. Claude picks expression category from the 3 CTR tiers based on video title
  3. Generate Eli vortex image via Gemini (character reference + expression + "popping out of blue plasma portal")
  4. Randomly pick one circle → replace its image with the vortex image
  5. Render glass orb/bubble borders on ALL circles (new PIL layer replacing current outline + energy ring)
  6. Skip the corner Eli overlay (removed)
Pros: Minimal new infrastructure. Stays within the existing Pillow compositing pipeline. One API call generates everything. Title card images can be re-composited without regenerating Eli.
B

Separate Eli vortex generation step

New API endpoint POST /api/eli/generate-thumbnail that generates the vortex image independently. Compositing then assembles it alongside circle images.

Trade-off: More flexible (can regenerate vortex image without re-running all compositing), but adds a new pipeline step the user has to trigger. More moving parts.
C

Modify one circle's generation prompt

During segment circle image generation, for the randomly picked segment, change its Gemini prompt to "Eli popping out of a portal" instead of the segment topic. No separate generation step.

Downside: Couples Eli vortex to the circle image generation pass. Can't regenerate Eli without regenerating all circle images. Less control over the vortex composition.
My recommendation: Option A

The existing title_card_composer.py already handles all the layering — background, circles, outlines, labels, Eli placement. We just modify what it composites:

  • Replace the solid outline + energy ring layers with glass orb rendering
  • Replace the corner Eli overlay with "pick one circle, use vortex image"
  • Add Claude expression selection call before Gemini image gen
  • The "recomposite" endpoint still works — it re-layers existing images
